# ADR-0006: 计算图现场物化，不预存文件

## Status

Accepted（2026-09-12）

## Context

有些外部框架（典型如 OpenMontage 的 `comfyui_video` 工具）**只接受**：

- 一个工作流 JSON 的**文件路径**
- 一个**输出节点 ID**（字符串）

它们不接受内存里的图对象，也不会替你注入任何参数。历史上是这样解决的：
用 `make_h3_workflow.py` 生成一份 JSON 存到共享目录，再通过两个环境变量
（`COMFYUI_MINIMAX_H3_WORKFLOW_PATH` 与 `_OUTPUT_NODE`，ref2v 另有一对）把路径告诉上游。

这套做法产生了几个实际故障：

1. **脱节**：仓库里存的 JSON 是某一时刻的快照。改了 `builder` 的节点顺序后，JSON 没重新生成，
   于是"代码里是对的、跑起来是旧的"。这类问题极难察觉，因为两边都不报错。
2. **变量污染**：为了记录"图在哪、输出节点是谁"，配置表里多了 4 个变量，
   而它们并不是用户的配置意图，只是实现细节的泄漏。
3. **多模式组合爆炸**：4 种模式（ref2v 还有单/双参考之分）× 每次要换 seed
   → 需要预生成的 JSON 组合无法穷举，最后还是得现场生成。

## Decision

**不预存任何计算图文件。** 提供 `om-bridge graph` 子命令，**现场物化**：

```bash
om-bridge graph -s minimax_h3.ref2v --ref-image a.png -o /tmp/h3.json --json
# → {"ok":true,"mode":"ref2v","output_node":"16","nodes":16,"path":"/tmp/h3.json","fingerprint":"..."}
```

落盘目录由方案自己决定（配置 `solution.<方案>.graph_dir`，默认 `<工作区>/var/graphs`），
外部脚本不必解析配置。

同时**从配置表中删除**那 4 个路径/节点变量，
并在 `config.py` 里留注释说明"已移除、不再读取"（避免旧 `.env` 让人困惑）。

该命令**刻意不联网**：物化的语义是"把代码里的构造结果写出来"，与后端是否可达无关。
需要连带校验就再跑 `om-bridge validate`。

## Alternatives Considered

**选项 B：继续预存 JSON，但加一个 CI 检查"仓库 JSON 与 builder 一致"。**
能防脱节，但要求每个消费方都跑 CI，且**组合爆炸问题没解决**（没法为所有 mode × seed 预存）。
另外它把"维护一份生成物"的成本永久留在了仓库里。不选。

**选项 C：预存 + 运行时自动检测过期并重新生成。**
需要"生成物携带生成时的代码指纹"，并在每次使用时校验——这实质上是把物化搬到了运行时，
却没去掉仓库里的文件。多了一份状态需要同步。比 D 差。不选。

**选项 D（采纳）：现场物化，不存。**
见上。

**选项 E：要求上游框架改成接受内存图/内联 JSON。**
改动上游是可行的（上游是自己维护的 fork），但：上游工具是通用件，
不该为某一个方案的特殊需求而改造；而且"文件路径 + 节点 ID"其实是个**合理的最小契约**
（适用于任何工作流引擎），没理由为了省一个命令而破坏它。不选。

## Consequences

**变容易的**：
- **不可能脱节**：图恒为"由当前代码现场生成"，生成即最新。
- 任意 mode × 任意 seed 组合都能支持，不必穷举。
- 配置表干净了：删掉 4 个实现细节泄漏的变量。
- 可以在**没有后端**的机器上物化（CI、跨机部署预生成），因为不联网。
- 物化产物带 `fingerprint`（载荷稳定哈希），便于判断"这份 JSON 与我预期的是否同源"。

**变难的 / 代价**：
- 外部框架的调用方多了一个步骤：**先调 `graph`，再调工具**。两步不可合并成一步
  （合并会让离线场景不可用）。
- 需要保证 `graph` 的输出**稳定**：同一输入必须产出逐字节相同的 JSON（键序稳定）。
  这一点靠 `builder` 的确定性来保证，并由模板回归测试看住。
- 用户若**重复提交同一份物化产物**，会命中后端整图缓存（见
  [minimax-h3.md](../solutions/minimax-h3.md) §8）。需要"换 seed 重新物化"，
  这必须写进文档和集成脚本里。

**后续要盯住的**：
- 若出现新的外部框架需要**别的形态**（例如一份内联 base64、或一个 HTTP 端点），
  应当**在这个命令上扩展输出格式**，而不是重开一条"预存文件"的路。
- `fingerprint` 目前只用于日志与比对。**不要**把它当缓存键使用：
  后端自己已有缓存语义（[architecture.md §11](../architecture.md)），
  再叠一层会让"缓存命中"与"真的算得快"无法区分。
